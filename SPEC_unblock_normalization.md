## 2. ЗАДАЧА A. Маппинг полей загрузчика (P0, блокер)

Файл: `backend/app/normalization/reference_loader.py`.

Проблема. `_pick` сопоставляет имена колонок точным равенством в нижнем регистре. Текущий `FIELD_ALIASES["service_name"]` не содержит `name_ru`, поэтому `name = None` для всех строк, и каждая строка отбрасывается на `if not name: continue`. Итог: 0 услуг. Аналогично теряются категория (`Специальность`) и код (`TarificatrCode`).

Правка. Расширить алиасы:

```python
FIELD_ALIASES = {
    "service_name": ("service_name", "name", "name_ru", "наименование", "услуга", "название"),
    "category":     ("category", "категория", "раздел", "группа", "специальность"),
    "icd_code":     ("icd_code", "icd", "мкб", "код", "tarificatrcode", "тарификатор", "код тарификатора"),
    "synonyms":     ("synonyms", "синонимы", "synonym"),
}
```

`name_ru` совпадёт с `Name_ru`, `специальность` с `Специальность`, `tarificatrcode` с `TarificatrCode` (сравнение идёт в нижнем регистре). Синонимов в файле нет, это нормально: `_pick(... "synonyms") or []` уже отрабатывает пусто, синонимы растут самообучением при ручной разметке.

Замечание о дедупликации. Загрузчик пропускает услугу, если уже есть запись с тем же `service_name_normalized`. В справочнике возможны одинаковые названия в разных специальностях с разными кодами тарификатора. Если при загрузке число услуг заметно меньше 1281, смени ключ дедупликации на пару (нормализованное имя + icd_code), чтобы не схлопывать разные услуги.

Код тарификатора кладём в существующее поле `Service.icd_code` (String(32)). Миграция не нужна, поле уже есть.

Критерий приёмки A. `python -m app.cli seed-reference "Справочник услуг.xlsx"` загружает примерно 1281 услугу. Выборочно: у записей заполнены `category` (специальность) и `icd_code` (код тарификатора).

## 3. ЗАДАЧА B. Level 0: матч по коду тарификатора (P1)

Это главный рычаг для 25%. Экстракторы уже сохраняют `service_code_source` (см. `pipeline/extractors/*` и `pipeline/base.py:27`), но каскад его игнорирует. Добавляем детерминированный уровень ПЕРЕД точным текстовым матчем.

### B.1 Новый метод матча

Файл: `backend/app/models/__init__.py`, enum `MatchMethod` (строка ~62). Добавить значение:

```python
class MatchMethod(str, enum.Enum):
    ...
    code = "code"
```

Поскольку колонка `PriceItem.match_method` это `SAEnum(MatchMethod)` в Postgres, при пересоздании БД из моделей всё ок. Если БД уже создана миграцией с готовым enum типом, добавь в миграцию `ALTER TYPE matchmethod ADD VALUE 'code';` или пересоздай БД (для демо мы поднимаем чистый Postgres).

### B.2 Нормализация кода и гомоглифы

Коды в справочнике латиницей (`A02.004.000`), а в прайсах из русских документов и OCR буквенный префикс может быть кириллическим гомоглифом (например `В02.110.002` у Клиники 3, где `В` это кириллица). Нужна нормализация перед сравнением. Добавь хелпер (рядом с `normalize.py`):

```python
_HOMO = str.maketrans({
    "А":"A","В":"B","Е":"E","К":"K","М":"M","Н":"H","О":"O",
    "Р":"P","С":"C","Т":"T","У":"Y","Х":"X",
})
def normalize_code(s: str | None) -> str | None:
    if not s:
        return None
    s = str(s).strip().upper().replace(" ", "")
    return s.translate(_HOMO) or None
```

### B.3 Индекс кодов

Где строится лексический индекс справочника (класс `LexicalIndex`), добавь карту `code -> [service]`: ключ `normalize_code(service.icd_code)`, значение список услуг (помним про 82 неуникальных кода, значит список, а не один объект). Метод `by_code(code) -> list[Service]`.

### B.4 Level 0 в каскаде

Файл: `backend/app/normalization/cascade.py`, метод `match`. Сигнатуру расширить кодом и добавить уровень в самом начале, до `exact`:

```python

                                [Candidate(s.service_id, s.service_name, 0.98, MatchMethod.code, 0)])
        if len(hits) > 1:
            # неоднозначный код: дизамбигуируем текстом ТОЛЬКО среди hits,
            # не уходя в общий справочник
            ...
    # дальше существующий каскад: exact -> fuzzy -> semantic -> rerank -> llm
```

Для неоднозначного кода (несколько услуг на один код) выбери лучшего по fuzzy или семантике среди `hits`, кандидатов в `MatchOutcome` ограничь этими `hits`.

### B.5 Передать код из вызова

Файл: `backend/app/normalization/match_service.py`, строка ~56. Сейчас:

```python
outcome = cascade.match(item.service_name_raw, item.category)
```

Стало:

```python
outcome = cascade.match(item.service_name_raw, item.category, item.service_code_source)
```

Критерий приёмки B. После загрузки справочника и `ingest docs` позиции Клиники 3 (несут код тарификатора) сопоставляются с `match_method = code` и `match_confidence >= 0.95`. Общий процент автоматча заметно выше, чем без кода. Коды Клиники 1 формата `U1.1` это внутренние коды клиники, они НЕ совпадут с тарификатором, это ожидаемо, они уходят в текстовый каскад.

## 4. ЗАДАЧА C. Снять жёсткий фильтр по категории (P1)

Файл: `backend/app/normalization/cascade.py`, метод `_semantic` (строки ~61 62):

```python
if category:
    stmt = stmt.where(Service.category == category)
```

Проблема. Категория справочника это специальность (`Акушер-гинеколог`, `Аллерголог`, 122 штуки). Категория из прайса это раздел документа (`ГЕМАТОЛОГИЯ`, `Консультации специалистов`). Это разные таксономии, пересечение почти нулевое. Жёсткое равенство `Service.category == category` выкидывает правильного кандидата и обнуляет recall семантики.

Правка. Убрать жёсткую фильтрацию по категории в `_semantic`. То же самое для лексического поиска: вызов `self.lexical.search(raw, limit=20, category=category)` (строка ~84) не должен фильтровать по равенству категории. Категорию допустимо оставить как мягкий бонус к скору при совпадении, но НЕ как фильтр отсечения. Самый простой безопасный вариант: перестать передавать `category` как фильтр (передавать `None` в фильтрующую ветку) и не трогать остальное.

Критерий приёмки C. Позиция из раздела с названием, не равным ни одной специальности справочника, всё равно находит правильную услугу. Регрессий по уже матчившимся позициям нет.

## 8. Guardrails: что НЕ трогать

- Не менять схему БД кроме добавления значения enum `code`. Код тарификатора живёт в существующем `icd_code`.
- Не переписывать экстракторы целиком. Задача E это точечные подтверждения и фикс склейки, не рефактор.

- Все изменения каскада сохраняют существующий порядок уровней (exact, fuzzy, semantic, rerank, llm). Мы только добавляем Level 0 перед ними и снимаем фильтр категории.
