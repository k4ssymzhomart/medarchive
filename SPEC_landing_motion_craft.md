## 1. Пять дисциплин (мерило для каждой анимации)

1. Сдержанность. По умолчанию всё неподвижно. Одно осмысленное движение на viewport.
2. Ритм. Высота, плотность и темп секций меняются намеренно. Асимметрия с причиной лучше симметрии по умолчанию.
3. Интенция. Каждое движение отвечает на вопрос «почему именно это движение». Если не отвечает, удалить.
4. Один сигнатурный момент. Решить, о чём страница, и потратить бюджет движения туда. Везде остальное тише.
5. Движение что-то значит. Направление, дистанция, тайминг подчинены смыслу. Данные движутся в ту сторону, куда течёт система.

Главный антипаттерн: один `<Reveal>` (fade-up 20px, 0.5s, ease-in-out) на каждом элементе. Заголовок появляется как футер. Движение перестаёт нести информацию и становится обоями.

## 2. Сигнатурный момент hero (демонстрируем продукт, не описываем)

Текущий hero статичен, поэтому и не нравится. Заменяем его на сцену, которая разрешается при скролле и показывает суть продукта: нормализацию.

Концепт. Hero держит неразрешённое состояние: несколько сырых, по разному названных строк ОДНОЙ услуги из разных прайсов, с разными клиниками и ценами. На первых примерно 60vh скролла они сходятся и нормализуются в ОДНУ каноническую запись справочника с кодом тарификатора и рядом цен клиник. Пользователь скроллом сам вызывает разрешение.

Пример данных (иллюстративный, но реалистичный, в духе реального архива):

```
Сырые строки (исходное состояние):
  Клиника 2  «Консультативный прием врача акушера гинеколога»   8 500 ₸
  Клиника 4  «Прием акушер гинеколога, первичный»               9 000 ₸
  Клиника 7  «Акуш. гинеколог, приём перв.»  (артефакт OCR)     7 500 ₸

Разрешается в каноническую запись справочника:
  «Прием акушер-гинеколога»   код тарификатора A02.004.000
  Цены: Клиника 2  8 500 ₸ · Клиника 4  9 000 ₸ · Клиника 7  7 500 ₸
```

Так hero за один жест показывает две ценности продукта сразу: объединение разных названий в одну услугу и сравнение цен по клиникам.

Реализация:
- Привязать к скроллу страницы (`useScroll` page-level), не к автоплею. Reader причиняет разрешение.
- Сырые карточки сходятся к канонической: используем `layoutId` для непрерывности (карточки путешествуют, не исчезают и появляются заново), пружина `snappy`.
- LCP заголовок (самый крупный текст) красится финально с первого кадра. Анимируется СЦЕНА со строками, НИКОГДА сам заголовок. Резерв `<Reveal>` только для контента ниже сгиба.
- Один момент, исполнить тщательнее всего остального. Под reduced-motion и на мобильном сцена показывает сразу финальное состояние (каноническая запись), без скролл сцены.

Это единственный сигнатурный момент страницы. Больше сигнатур не добавлять.

## 3. Моушн система (токены, один источник правды)

Вынести в `frontend/src/lib/easing.ts` и `frontend/src/lib/motion.ts`, чтобы продукт переиспользовал.

Easing (асимметрия: ease-out на вход, ease-in на выход):

```ts
export const ease = {
  out:     [0.16, 1, 0.3, 1],   // рабочая лошадка: быстрый старт, долгий доезд
  outSoft: [0.22, 1, 0.36, 1],  // мягче, для крупных элементов
  in:      [0.4, 0, 1, 1],      // выходы: ускорение прочь
} as const;
```

Пружины (для интеракций, не для opacity):

```ts
export const spring = {
  soft:   { type: "spring", stiffness: 100, damping: 20, mass: 1 },
  snappy: { type: "spring", stiffness: 400, damping: 30, mass: 0.8 },
  heavy:  { type: "spring", stiffness: 120, damping: 26, mass: 1.4 },
} as const;
export const scrubSpring = { stiffness: 120, damping: 30, mass: 0.4 } as const; // сглаживание scroll прогресса
```

Лестница длительностей: микро 80 150мс, мелкий UI 200мс, карточки 320мс, секции 500мс, крупный hero 600 800мс (потолок). Контраст быстрых мелких и медленных крупных создаёт ощущение массы.

Stagger: 0.04 0.06 для коротких списков, 0.06 0.08 для карточек, не больше. Исключение: 2 4 крупные строки hero допускают 0.10 0.12. Для сеток считать задержку от (row+col), чтобы волна шла по диагонали.

Семейство Reveal (вместо одного варианта). Один компонент, проп `intent`:

```ts
const reveals = {
  statement: { hidden: { opacity: 0, y: 12 }, show: { opacity: 1, y: 0, transition: { type: "spring", stiffness: 420, damping: 32, mass: 0.9 } } },
  evidence:  { hidden: { opacity: 0 },        show: { opacity: 1, transition: { duration: 0.4, ease: ease.outSoft } } }, // без дрейфа: достоверность это покой
  sequence:  { hidden: { opacity: 0, y: 8 },  show: { opacity: 1, y: 0, transition: { duration: 0.45, ease: ease.out } } }, // с staggerChildren на родителе
};
```

Reveal принимает `amount`, `margin`, `delay`, вариант. Порог `amount`: мелкие элементы 0.4 0.6, высокие секции 0.15 0.25. `margin: '0px 0px -10% 0px'` чтобы срабатывало чуть раньше сгиба. `once: true` для контента.

## 4. Lenis (плавный скролл), настроенный

Добавить `lenis`, обернуть приложение один раз высоко в дереве (provider компонент, без App Router). Настройка против «ваты»:

```tsx
// lerp 0.085 (снаппи, но плавно), wheelMultiplier 1 (НЕ повышать),
// smoothWheel true, syncTouch false (нативный тач не трогаем), autoRaf false
// и кормить RAF Lenis в frame.update из framer-motion, чтобы useScroll и Lenis шли на одних часах.
```

Жёсткие правила:
- `lerp` в диапазоне 0.07 0.1. Ниже 0.06 укачивает, выше 0.12 смысла нет.
- `wheelMultiplier` не больше 1.
- `syncTouch: false`. На тач отдаём нативную инерцию.
- Под `prefers-reduced-motion` Lenis НЕ монтировать вообще, рендерить `children` как есть.
- На ширине меньше 768px Lenis отключить, скролл нативный.
- Якорные ссылки гонять через `lenis.scrollTo`, иначе нативный прыжок дерётся со сглаженным скроллом.

Скролл это таймлайн, который ты авторишь. Скраб (`useScroll` плюс `useTransform`, сглаженный `useSpring(scrubSpring)`) только для одного двух мест, которые и есть аргумент (наш hero resolve). Остальное это триггер один раз (`whileInView`). Для не рендерных side эффектов по скроллу использовать `useMotionValueEvent`, не `useState` (иначе ре рендер каждый кадр).

## 5. Применение по секциям (различать, не копировать)

Каждой секции свой моушн концепт по смыслу, не один и тот же fade-up.

- Hero: сигнатурный resolve из раздела 2 (скрабится скроллом).
- Лента логотипов: marquee, реагирующий на скорость скролла (`useVelocity(scrollY)` подмешать в базовую скорость), база медленная 25 40px/с. Не постоянная CSS лента по дефолту.
- Ценность: statement reveal. Можно построчная маска (`overflow-hidden` родитель, строки из `y: 110%` в `0`, stagger 60 80мс). По словам для заголовков, не по буквам.
- Тёмная фича секция: три мини карточки появляются в порядке потока данных (извлечение → нормализация → проверка), `sequence` с `staggerChildren`, а не синхронной сеткой. Последовательность это объяснение, сетка это просто «вот три фичи».
- Метрики: число считается вверх ОДИН раз при первом появлении, не больше 1.2с, `ease.out`, без отскока, только реальные цифры проекта, только ниже сгиба. Движение допустимо (подразумевает измерение), отскок запрещён (подразумевает праздник).
- Финальный CTA и футер: спокойный доезд, выходы через `AnimatePresence` где есть условный рендер (выход вдвое быстрее входа, `ease.in`).
- Швы между секциями: фон (сетка или градиент) живёт сквозь все секции и меняет плотность или прозрачность как функцию глобального скролл прогресса. Параллакс только на фоне, маленький (40 100px), никогда на читаемом тексте.

## 6. Пол качества (производительность и доступность, не обсуждается)

- Анимировать только `transform` и `opacity`. Никаких `top`, `height`, `margin`, `box-shadow`, `filter` в анимации. Для свечения кросс фейдить opacity заранее отрисованного слоя тени, не сам `box-shadow`.
- `will-change: transform` только на время активной анимации, потом снять. Не вешать на десяток секций.
- Не читать layout (`getBoundingClientRect`, `offsetTop`) внутри scroll или rAF колбэка. Не вешать сырые `scroll` слушатели, всё через `useScroll`.
- LCP заголовок hero красится финально с первого кадра. Его не анимировать.
- `prefers-reduced-motion`: обернуть в `<MotionConfig reducedMotion="user">`, убить Lenis и параллакс, проверить, что КАЖДАЯ секция разрешается в видимое финальное состояние (не пустую). Плюс CSS медиа фолбэк.
- Мобильный меньше 768px: Lenis выключен, параллакс в ноль, скрабовые сцены заменить на `whileInView` один раз.
- Не угонять скролл, пины ограничены по дистанции. Фокус с клавиатуры ведёт страницу (`focusin` → `lenis.scrollTo`). Скроллируемые регионы с `role` и `aria-label`.
- Тяжёлые offscreen секции: `content-visibility: auto` плюс `contain-intrinsic-size`. Самые тяжёлые монтировать лениво через `React.lazy` плюс `Suspense` с заглушкой высоты (без сдвига layout).
- Цель 60fps. Профилировать: Performance запись скролла, Rendering → Paint flashing. На скролле почти нет зелёного, только композитор двигает слои.

## 7. Порядок работы (не пропускать стадии)

1. Грейбокс: hero и секции хороши в статике, без движения. Если скучно замороженным, движение не спасёт. Здесь же разнобой высот секций (hero просторный, плотные и дышащие чередуются).
2. Один сигнатурный момент: hero resolve до высокого финиша в изоляции.
3. Моушн пасс: добавить движение остальным, каждому свой концепт по смыслу. Семейство Reveal с intent, не один вариант.
4. Пасс сдержанности: удалить примерно половину анимаций. Тест каждой: если убрать, страница хуже доносит смысл? Если нет, это был декор. Выживают сигнатурный момент, вход hero, появление метрик.
5. Микро полировка: ритм stagger, easing, выходы, отсутствие CLS, фокус.

Самокритика перед PR (каждое «нет» это след генерации):
- Высоты секций различаются намеренно.
- Один фокальный элемент на сцену.
- Дефолтный easing заменён на осмысленные кривые.
- Stagger зависит от веса контента, не плоский 0.1.
- Ровно один сигнатурный момент, его можно назвать словами.
- Страница переживает отключение Lenis (моушн не костыль).
- `prefers-reduced-motion` реально работает, история читается мгновенными состояниями.
- Нет движения на критичном тексте сгиба (заголовок читается в первые 100мс).
