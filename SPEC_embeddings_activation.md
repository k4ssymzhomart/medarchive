## 2. Задача 1. Ключ и чистый прогон (P0)

Ключ. Пользователь сам добавит `OPENAI_API_KEY` в gitignored `.env` локально. НИКОГДА не коммить ключ, не печатать его в логах, не вставлять в файлы. Ключ уже перевыпущен после утечки.

Конфиг. Менять не нужно (provider, model, dim уже верные). Проверь только, что `.env` читается и `settings.openai_api_key` не пуст в контейнере.

Чистый прогон (важно: старое состояние матчей из прогона без ключа надо сбросить):

```
docker compose down -v          # чистый том БД, иначе мешает старое состояние матчей
docker compose up --build -d
docker compose exec backend python -m app.cli seed-reference "Справочник услуг.xlsx"
docker compose exec backend python -m app.cli ingest docs
```

При `seed-reference` с ключом услуги эмбеддятся пакетно (`embed_batch`). При `ingest` позиции эмбеддятся и матчатся через семантический уровень.

Критерий приёмки 1. `Service.embedding` заполнен (не NULL) примерно у 1231 услуги. Проверка: SELECT count(*) FROM services WHERE embedding IS NOT NULL.

## 3. Задача 2. Независимые порты (P1)

Требование пользователя: проект полностью автономен, никакой связи с другими проектами, порты фиксированы и закоммичены, НИКАКОГО динамического ремапа по факту наличия чужих контейнеров.

Правка `docker-compose.yml`: вынести хост-порты в переменные с выделенными дефолтами medarchive (контейнерные порты не трогаем):

```yaml
# backend
ports:
  - "${APP_PORT:-8088}:8000"
# postgres
ports:
  - "${DB_PORT:-5544}:5432"
# redis
ports:
  - "${REDIS_PORT:-6399}:6379"
```

Добавить `APP_PORT`, `DB_PORT`, `REDIS_PORT` в `.env.example` с этими дефолтами и комментарием. Дефолты выбраны так, чтобы не пересекаться с типовыми 8000/5432/6379. Если позже захочется именно 8000 — это одна строка в `.env` (`APP_PORT=8000`), без правок кода.

Критерий приёмки 2. `docker compose up` поднимается на выделенных портах при любом наборе чужих запущенных проектов. Никакой логики определения/ремапа чужих портов в репозитории нет.
