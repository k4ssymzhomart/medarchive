# Совместная работа

Работаем по пяти трекам из раздела 14 документа стратегии. Точки синхронизации
на контрактах (схема БД и OpenAPI), а не на готовом коде.

## Ветки

- `main` — стабильная, защищена, деплой по push.
- Рабочие ветки именуем по треку и задаче: `track-a/pdf-scan-ocr`,
  `track-c/search-fts`, `track-d/verification-queue`.
- Один PR на задачу, привязан к issue через `Closes #N`.

## Процесс

1. Берём issue из доски, переводим в In Progress.
2. Создаём ветку от `main`.
3. Делаем изменение, держим контракт (схему БД и OpenAPI) как источник правды.
4. Открываем PR по шаблону, дожидаемся зелёного CI и ревью.
5. Squash merge в `main`.

## Правила кода

Backend: ruff чистый, тесты проходят, `python -m compileall` без ошибок.
Frontend: строгие дизайн правила (раздел 11.1). Светлая тема, монохром плюс один
акцент, острые углы, шрифт Space Grotesk, иконки только lucide react, ноль
эмодзи, без дефисов в текстах интерфейса, всё на русском.

## Локальный запуск

См. README. Один `docker compose up --build` поднимает весь стек.
